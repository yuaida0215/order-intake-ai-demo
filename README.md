# 受注取り込みAI Agent デモ

商品販売会社向け「受注取り込みAI Agent」の**営業デモ**アプリです。
FAX・PDF・メール・Slack/Teams・EDI などバラバラのチャネルで届く受注を、
AIが「読み取り → 構造化 → 分類 → 自動入力／担当者振り分け」する一連の業務体験を、クリック操作で見せられます。

> ⚠️ 本番システムではありません。OCR・メール送信・基幹システム連携はすべて**モック**です（要件定義書 §1.2）。

## 起動方法（ローカル）

```bash
npm install      # 初回のみ（導入済み）
npm run dev      # → http://localhost:3300
```

ローカルは `.env.local` の `APP_PASSWORD` でログインします。ブラウザで <http://localhost:3300> を開きます。

## 実チャネル取り込み（Chatwork / Slack / メール）

受注一覧の「取り込み:」ボタン群、または「受注アラート」画面の自動監視から、**本物のチャネル**の
直近メッセージをAI（claude-opus-4-8）で会話スレッド単位（3〜10通・時間近接でグルーピング）にまとめ、
受注らしさを判定して**受注アラート**として追加できる。同じスレッドの二重取り込みは自動スキップ
（アラートの承諾/アーカイブ後、会話が進展すれば新しいスレッドとして再検知される）。
共通エンジンは `lib/ingest-server.ts`。

必要な環境変数（ローカル=.env.local、本番=Vercelダッシュボード。共通で `ANTHROPIC_API_KEY` も必須）:

| チャネル | 環境変数 | 取得方法 |
|---|---|---|
| Chatwork | `CHATWORK_API_TOKEN` / `CHATWORK_ROOM_ID` | Chatwork設定→API。ルームIDはルームURLの `#!rid` 以降 |
| Slack | `SLACK_BOT_TOKEN` / `SLACK_CHANNEL_ID` | api.slack.com/apps でApp作成→Bot Token Scopes に `channels:history`+`users:read`→Install→xoxb-トークン。Botを対象チャンネルに `/invite`。チャンネルIDはチャンネル詳細の最下部 |
| メール(Gmail) | `GMAIL_ADDRESS` / `GMAIL_APP_PASSWORD` | Google 2段階認証を有効化→ myaccount.google.com/apppasswords で16桁のアプリパスワードを発行（IMAP接続に使用） |

未設定のチャネルはボタンを押すと「環境変数◯◯が未設定です」と案内が出るだけで、他チャネルには影響しない。

## 画面（要件定義書の5画面 + 機能拡張分）

| 画面 | URL | 内容 |
|---|---|---|
| SCR-001 受注一覧 | `/orders` | KPI・フィルター・AI一括読み取り演出・全案件一覧・受注アラートバンド |
| SCR-002 AI読み取り | `/orders/:id/read` | 元データ（単発 or 会話ラリー）と抽出結果を左右で比較・信頼度・不足項目・次のアクション4ボタン |
| SCR-003 基幹システム自動入力 | `/orders/:id/core-system-input` | ERP風フォームへAIが順番に自動入力→受注番号採番（発注書転記時も同じ画面を再利用） |
| SCR-004 例外案件・返信ドラフト | `/orders/:id/exception` | A/B/C/D別の対応・相手先への確認文面の編集/送信 |
| SCR-005 月次ダッシュボード | `/dashboard` | KPI・グラフ・自社/相手先対応待ちリスト |
| 受注アラート | `/alerts` | AI会話監視モニター（自動監視ON/OFF・実チャネルスキャン）・受注アラートの確認/アーカイブ |
| 見積書作成 | `/orders/:id/quote` | AIが見積書を自動生成→編集→先方送付 or 上長確認依頼 |
| 上長確認待ち | `/approvals` | 自動リマインド設定（ツール・経過営業日）・デモ内営業日時計・承認/差し戻し |
| 発注書確認 | `/orders/:id/po` | 届いた発注書の内容確認→基幹システムへ転記 |
| 対応状況一覧 | `/tasks` | 全案件・全アラートを横断して「誰が何をすべきか」を一覧表示 |

## おすすめのデモ手順（約3〜4分）

1. **受注一覧**（`/orders`）で「🤖 AIで一括読み取り」を押す
   → 8件の受注がAI読み取り中→分類され、KPI・受注金額が反映される
2. **正常案件**（株式会社東京ストア）の行を開く → 抽出結果を確認 → 「基幹システムへ入力」
   → 自動入力アニメーション → **受注番号が採番**される
3. **相手先不備（C）**（西日本小売）を開く → AIが作った確認依頼文面を編集 → 「送信する」
   → ステータスが「相手先返信待ち」に変わる
4. **一部虫食い（B）／バリデーションエラー（D）** は自社で補完・修正すると自動処理を再開できる
5. **月次ダッシュボード**（`/dashboard`）で受注金額・自動処理率・対応待ちを確認
6. 左下「↺ デモをリセット」でいつでも最初の状態に戻せます

### 追加機能のデモ手順（受注アラート〜承認〜発注書、約2〜3分）

1. **受注アラート**（`/alerts`）を開く → 山田製作所（受注確定発言あり）の会話を確認 →
   「🤖 AIで読み取る」→ 抽出結果が表示される（要不足項目なら例外画面へ、揃っていれば次のアクションへ）
2. 鈴木商店の会話（受注の可能性あり・確定発言なし）は「この会話はまだ受注ではない」でアーカイブできる
3. 「自動監視を開始」を押すと、数秒おきに新しい会話・発注書のアラートが追加される
4. 条件が揃った会話を読み取った後、「📄 見積書作成」→ 見積書が自動生成される →
   内容を編集し「👤 上長に確認依頼」
5. **上長確認待ち**（`/approvals`）を開く → リマインド設定（ツール・経過営業日）を確認 →
   「⏩ 1営業日進める」を数回押すと、設定した営業日を超えた案件に自動でリマインドが送信される
   → 「✓ 承認する」で確定
6. 発注書アラートの「内容を確認する」→ **発注書確認画面**（`/orders/:id/po`）で内容を確認 →
   「🤖 自動的に基幹システムに転記する」→ 既存の基幹システム自動入力画面に合流し受注番号が採番される
7. **対応状況一覧**（`/tasks`）で、自社・上長・相手先・AIの誰が何をすべきかを横断確認

## 分類ロジック（要件定義書 §5）

| 分類 | 例 | 対応 |
|---|---|---|
| 正常 | 必須項目が揃い信頼度≥0.85 | AIが基幹システムへ自動入力 |
| A 読み取り失敗 | FAX不鮮明で判読不可 | 自社担当が手入力 |
| B 一部虫食い | 一部項目のみ不明 | 自社担当が補完 |
| C 相手先不備 | 受注書に必須情報が無い | AIが相手先へ確認依頼を生成・送信 |
| D バリデーションエラー | 商品コードがマスタに無い等 | 自社担当が修正 |

## 技術構成

- Next.js 14（App Router）/ React 18 / TypeScript
- Tailwind CSS
- Zustand（デモ状態のクライアント管理）
- チャート・アニメーションは外部ライブラリ非依存の自前実装

## ディレクトリ

```
app/            画面（各ルート。alerts / approvals / tasks / orders/[id]/{quote,po} を追加）
components/      共通UI（サイドバー・バッジ・KPI・元データプレビュー・会話プレビュー・見積書シート等）
lib/            types / data(サンプル8件+アラート5件) / store / 表示ヘルパ / 基幹入力ヘルパ /
                営業日計算(business-days) / 対応状況導出(tasks) / 実チャネル取り込み(ingest-server)
```

サンプルデータは `lib/data.ts` に集約。取引先名・商品・金額などを差し替えれば、
商談相手に合わせたデモにカスタマイズできます。
